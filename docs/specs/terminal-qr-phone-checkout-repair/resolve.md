# Terminal QR phone checkout repair — resolution

## Settled contract decisions

| Decision | Resolution |
| --- | --- |
| Initial terminal QR | Preserve the existing `/checkin?...courseSlug/date/time/durationMinutes/fromQr=1` QR generated by `/staff/terminal`. |
| Payment surface | Preserve the signed-out/signed-in QR-phone journey and its Stripe Checkout Session route. Do not introduce direct payment, a new QR, or PaymentIntent migration. |
| Client contract | QR-phone check-in card submission must retain `photoContext: "qr_phone"` and `checkInBooking: true`, use the returned hosted Stripe URL, and navigate to it. |
| Stripe method type | Preserve `payment_method_types: ["card"]`; changing it is not authorized by this repair without new evidence. |
| Wallet expectation | Apple Pay and other card wallets are eligibility-dependent provider behavior, not a UI-code promise. |
| Duplicate label | Remove only CourseCardPanel's outer heading in the compact+past-courses path. The CourseCardContent heading is the single retained label. |
| Production | Local work neither proves deployment nor authorizes deployment. Provider eligibility and deployed revision are separately verifiable. |

## Explicit exclusions

The following remain unchanged: account and identity logic, selected product, amount, fulfillment, Stripe webhook behavior, kiosk-generated hosted-checkout QR, tablet embedded fallback, native M2, and all production configuration.

- Use the current focused test files; do not add dependencies or test infrastructure.
